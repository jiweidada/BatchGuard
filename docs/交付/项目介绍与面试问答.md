# BatchGuard 项目介绍与面试问答

> 适用版本：0.1.0。
>
> 分类：交付。

## 1. 60 秒项目介绍

BatchGuard 是一个使用 C++20 和 CMake 开发的 Windows 重复文件检查工具。用户
提供目录后，程序递归发现普通文件，先按文件大小筛掉不可能重复的文件，再通过
Windows CNG 计算 SHA-256，并按“大小 + 哈希”生成重复组。核心库与 CLI 展示层
分离，扫描过程只读；权限、占用和文件变化等预期失败会进入报告，不会终止整个
批次。候选文件使用有界工作线程并发哈希，进度由扫描线程汇聚后再交给控制台，
保证输出线程安全。项目包含 Debug、Release 构建和覆盖完整扫描流程的自动化测试。

## 2. 演示流程

在已经加载 MSVC 环境的终端中执行：

```powershell
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/release
ctest --test-dir build/release --output-on-failure
.\build\release\BatchGuard.exe --version
.\build\release\BatchGuard.exe --help
.\build\release\BatchGuard.exe --hash-workers 4 "<演示目录>"
```

演示时说明：

1. 程序只扫描，不执行删除、移动或修改。
2. 发现阶段总数未知，因此显示累计文件数。
3. 哈希进度按候选总字节数计算，不按文件个数计算。
4. 标准输出重定向时关闭动态进度，只保留最终报告。
5. 发现重复文件仍返回 `0`；局部文件失败返回 `2`。

## 3. 核心数据流

```text
目录参数
  ↓
输入验证
  ↓
普通文件列表 + 发现失败
  ↓
文件大小元数据 + 同大小候选
  ↓
有界并发 SHA-256 + 哈希失败
  ↓
重复文件组
  ↓
ScanReport
  ↓
中文输出 + 退出码
```

## 4. 关键设计取舍

### 为什么先比较文件大小

大小不同的文件不可能内容完全相同。先按大小分组，可以避免为大量唯一大小文件
读取内容和计算哈希。

### 为什么使用 SHA-256

SHA-256 有稳定、成熟的系统实现，碰撞风险适合重复文件检查。项目使用 Windows
CNG，不需要新增密码学第三方依赖。

### 为什么使用“大小 + SHA-256”

文件大小让候选筛选更高效，也让重复键的语义更明确。文件名和路径不参与重复判断，
因此不同目录、不同名称的文件仍能进入同一组。

### 为什么单文件失败不抛出全局异常

权限不足、文件被占用或扫描过程中消失是批处理中的预期情况。把这些失败记录到
报告可以保留已完成结果，并让退出码 `2` 明确表达“扫描完成但存在局部失败”。

### 多线程如何避免数据竞争

工作线程通过原子索引领取任务，每个任务写入独立的预分配结果槽。汇总进度使用
互斥量保护，扫描线程在释放锁后调用外部回调。文件 I/O、哈希和控制台回调均不在
持锁期间执行。

### 为什么默认最多 4 个哈希线程

哈希同时消耗存储吞吐和 CPU。过多线程可能让机械盘或网络盘发生争用，因此自动
模式采用保守上限；用户可以通过 `--hash-workers` 根据实际介质调节。

## 5. 常见面试问答

### 核心库为什么不能依赖 CLI

扫描、哈希和重复分组是可复用业务能力。让依赖方向保持
`CLI → batchguard_core`，核心逻辑就能独立测试，也能被未来 GUI 复用。

### 如何保证扫描结果稳定

发现路径、失败项、重复组成员和重复组本身都使用明确规则排序。线程完成顺序不会
决定最终报告顺序，因此重复运行可以得到一致输出。

### RAII 用在了哪些地方

测试临时目录、Windows 文件句柄、CNG 算法句柄、CNG 哈希句柄和工作线程都有明确
所有者，并在对象析构时自动释放或汇合。

### 为什么使用 `std::error_code`

文件系统预期失败不应依赖异常控制整个批次。`std::error_code` 能保留底层错误，
同时让调用方决定记录失败并继续处理。

### 如何测试多线程确实运行

调度器测试注入可控的假哈希操作，通过条件变量让两个任务同时进入操作，并记录
工作线程 ID；测试不依赖“必须在多少毫秒内完成”这类易波动的性能断言。

### 当前版本还没有什么

0.1.0 不提供文件删除、移动、报告导出、历史记录、实时监控、取消或 GUI。网络盘
可以扫描，但最佳并发度需要按实际存储环境测量。
