# BatchGuard 项目介绍与面试问答

> 适用版本：0.2.0。
>
> 分类：交付。

## 1. 60 秒项目介绍

BatchGuard 是一个使用 C++20、CMake 和 Qt Widgets 开发的 Windows 重复文件检查
工具，同时提供 CLI 和只读 GUI。程序递归发现普通文件，先按文件大小筛选候选，
再通过 Windows CNG 计算 SHA-256，并按“大小 + 哈希”生成重复组。纯 C++ 核心与
两个应用层保持分离；权限、占用和文件变化等预期失败进入报告，不会终止整个批次。
候选文件使用有界工作线程并发哈希，GUI 通过专用 Qt 线程调用核心，并使用
`std::stop_token` 安全取消。项目还提供结构化日志、结果主从模型、Debug/Release
构建以及 GoogleTest、Qt Test 和 CTest 自动化验证。

## 2. 演示流程

在已经加载 MSVC 环境的终端中执行：

```powershell
cmake --build cmake-build-release
ctest --test-dir cmake-build-release --output-on-failure
.\cmake-build-release\BatchGuard.exe --version
.\cmake-build-release\BatchGuard.exe --hash-workers 4 "<演示目录>"
.\cmake-build-release\BatchGuardGui.exe
```

首次建立 Release Profile、独立部署目录和干净环境验收时，按
[v0.2.0部署说明.md](v0.2.0部署说明.md) 配置 Qt、运行库和许可材料。

演示时说明：

1. 程序只扫描，不执行删除、移动或修改。
2. 发现阶段总数未知，因此显示累计文件数。
3. 哈希进度按候选总字节数计算，不按文件个数计算。
4. 标准输出重定向时关闭动态进度，只保留最终报告。
5. 发现重复文件仍返回 `0`；局部文件失败返回 `2`。
6. GUI 扫描在后台线程执行，取消是协作式停止，不强制终止线程。
7. “理论可节省空间”是逻辑大小估算，GUI 不执行删除或清理。
8. 日志不记录输入目录或文件完整路径，也不写日志文件。

## 3. 核心数据流

```text
目录参数
  ↓
输入验证
  ↓
普通文件列表 + 发现失败
  ↓
文件大小元数据 + 同大小候选
  ↓
有界并发 SHA-256 + 哈希失败
  ↓
重复文件组
  ↓
ScanReport
  ├──→ CLI 中文报告 + 退出码
  └──→ GUI 结论摘要 + 重复组主从视图 + 失败详情
```

## 4. 关键设计取舍

### 为什么先比较文件大小

大小不同的文件不可能内容完全相同。先按大小分组，可以避免为大量唯一大小文件
读取内容和计算哈希。

### 为什么使用 SHA-256

SHA-256 有稳定、成熟的系统实现，碰撞风险适合重复文件检查。项目使用 Windows
CNG，不需要新增密码学第三方依赖。

### 为什么使用“大小 + SHA-256”

文件大小让候选筛选更高效，也让重复键的语义更明确。文件名和路径不参与重复判断，
因此不同目录、不同名称的文件仍能进入同一组。

### 为什么单文件失败不抛出全局异常

权限不足、文件被占用或扫描过程中消失是批处理中的预期情况。把这些失败记录到
报告可以保留已完成结果，并让退出码 `2` 明确表达“扫描完成但存在局部失败”。

### 多线程如何避免数据竞争

工作线程通过原子索引领取任务，每个任务写入独立的预分配结果槽。汇总进度使用
互斥量保护，扫描线程在释放锁后调用外部回调。文件 I/O、哈希和控制台回调均不在
持锁期间执行。

### 为什么默认最多 4 个哈希线程

哈希同时消耗存储吞吐和 CPU。过多线程可能让机械盘或网络盘发生争用，因此自动
模式采用保守上限；用户可以通过 `--hash-workers` 根据实际介质调节。

### 为什么 GUI 还需要一个专用扫描线程

核心扫描接口是同步的。GUI 把一次完整扫描放入专用 `QThread`，主线程只处理
控件、模型和窗口事件，避免界面无响应。核心内部仍只负责文件级有界并发，GUI
不会为每个文件再创建线程。

### 为什么取消使用 `std::stop_token`

核心扫描不依赖 Qt，`QThread::requestInterruption()` 无法自动停止纯 C++ 文件
扫描。控制器使用线程安全的停止源发出请求，核心在发现、元数据、任务领取、
单文件读取块和重复分组边界检查令牌，并通过 RAII 回收全部线程。

### 为什么日志库不放进核心库

核心只提供扫描数据和进度事件，不决定输出位置。CLI 和 GUI 应用层把同一结构化
记录分别路由到终端和 GUI 日志模型，保持核心可复用，也避免测试依赖输出设施。

## 5. 常见面试问答

### 核心库为什么不能依赖 CLI

扫描、哈希和重复分组是可复用业务能力。让依赖方向保持
`CLI/GUI 支持层 → batchguard_core`，核心逻辑就能独立测试，Qt 类型也不会进入
公共核心接口。

### 如何保证扫描结果稳定

发现路径、失败项、重复组成员和重复组本身都使用明确规则排序。线程完成顺序不会
决定最终报告顺序，因此重复运行可以得到一致输出。

### RAII 用在了哪些地方

测试临时目录、Windows 文件句柄、CNG 算法句柄、CNG 哈希句柄和工作线程都有明确
所有者，并在对象析构时自动释放或汇合。

### 为什么使用 `std::error_code`

文件系统预期失败不应依赖异常控制整个批次。`std::error_code` 能保留底层错误，
同时让调用方决定记录失败并继续处理。

### 如何测试多线程确实运行

调度器测试注入可控的假哈希操作，通过条件变量让两个任务同时进入操作，并记录
工作线程 ID；测试不依赖“必须在多少毫秒内完成”这类易波动的性能断言。

### 当前版本还没有什么

0.2.0 不提供文件删除、移动、重命名、报告导出、历史记录、实时监控、多目录扫描
或暂停后继续。GUI 支持安全取消，但取消结果不会把部分报告展示为完整结果。网络盘
可以扫描，最佳并发度仍需按实际存储环境测量。Qt 5.14.2 已是归档版本，长期维护
需要单独评估 Qt 6。
