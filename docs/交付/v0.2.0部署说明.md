# BatchGuard 0.2.0 Windows 部署说明

> 验证日期：2026-07-31。
>
> 目标：Windows x64，MSVC 19.29，Qt 5.14.2 `msvc2017_64`。

## 1. Release 构建

在已经加载 Visual Studio 2019 x64 开发环境的终端中配置：

```powershell
cmake -S . -B cmake-build-release -G Ninja `
    -DCMAKE_BUILD_TYPE=Release `
    -DBATCHGUARD_BUILD_GUI=ON `
    -DBATCHGUARD_BUILD_TESTS=ON `
    -DCMAKE_PREFIX_PATH="<Qt 5.14.2 msvc2017_64 目录>"
cmake --build cmake-build-release
ctest --test-dir cmake-build-release --output-on-failure
```

CMake 会在 GUI 链接后调用同一 Qt 套件的 `windeployqt`，因此构建目录中的
`BatchGuardGui.exe` 可以直接用于本机验证。

## 2. 独立部署目录

发布目录至少包含：

```text
BatchGuard.exe
BatchGuardGui.exe
Qt5Core.dll
Qt5Gui.dll
Qt5Widgets.dll
platforms/qwindows.dll
LICENSE.Qt.txt
```

使用 `windeployqt --release --no-translations` 收集实际运行依赖。调用时应让目标
Qt 的 `bin` 位于 PATH 首位；如果终端中存在 Anaconda 等其他 Qt 发行版，
`windeployqt` 可能解析到错误的 Qt DLL。可以使用 `cmake -E env` 为该命令提供
只包含目标 Qt 和 Windows 系统目录的临时 PATH。

阶段 18 的实际部署还包含 Qt SVG、Windows Vista 样式和常用图像格式插件，共
22 个文件、47,463,394 字节。部署目录没有 Debug Qt DLL。

## 3. 干净环境验收

在不依赖开发机 Qt 环境变量的条件下：

1. 清除进程级 `QT_PLUGIN_PATH` 和 `QML2_IMPORT_PATH`。
2. PATH 仅保留 Windows 系统目录。
3. 从部署目录执行 `BatchGuard.exe --version`。
4. 启动 `BatchGuardGui.exe`，确认主窗口出现并正常关闭。

阶段 18 实测 CLI 输出 `BatchGuard 0.2.0` 并返回 `0`；GUI 创建主窗口、优雅关闭
并返回 `0`。

## 4. 运行库与许可证

- 目标机器需要 Microsoft Visual C++ 2019 x64 Redistributable。
- Qt 5.14.2 以动态库方式部署，DLL 和插件可被用户替换。
- 发布目录应包含 Qt 安装包 `Licenses/LICENSE` 的原始副本，并命名为
  `LICENSE.Qt.txt`。
- 该许可文件说明 Qt 开源组件的 LGPLv3/GPLv3 条款；正式分发前由发布方确认
  采用的许可路径、模块范围和第三方组件义务。
- BatchGuard 仓库当前没有单独声明源码许可证；对外开源或再分发前由所有者决定。
