## 1. 一句话目标

使用 C++20 开发一个本地文件检查工具：扫描指定目录，根据文件内容识别重复文件，
记录处理失败原因，并以清晰、可验证的方式输出结果。

## 2. 项目价值

### 对使用者

- 找出名称不同但内容相同的文件。
- 在不修改原文件的前提下了解目录中的重复情况。
- 明确看到无法读取、扫描失败等异常，而不是静默遗漏。

### 对开发者

- 完整经历需求、架构、编码、测试和交付过程。
- 练习 C++20 的资源管理、类型设计、文件系统和错误处理。
- 学习使用 CMake 划分库、应用和测试目标。
- 在功能正确后逐步引入并发、取消和客户端界面。
- 最终能够独立解释每项设计，而不只是让程序运行。

## 3. 目标用户与场景

第一版面向需要整理本地目录的个人用户或开发者。

典型流程：

1. 用户向程序提供一个本地目录。
2. 程序检查输入并递归发现普通文件。
3. 程序读取文件内容并生成内容指纹。
4. 程序根据内容指纹建立重复文件分组。
5. 程序输出扫描统计、重复组和失败记录。
6. 程序只生成报告，不自动删除或移动任何文件。

## 4. 第一版 MVP

第一版只做一个可测试的命令行程序，包含：

- 接收一个待扫描目录。
- 递归扫描普通文件。
- 为可读取文件计算内容指纹。
- 将内容相同的文件归入同一重复组。
- 输出文件总数、重复组和失败原因。
- 使用退出码区分成功、输入错误和运行失败。
- 对核心流程提供自动化测试。

内容指纹算法、命令行参数格式和结果展示格式将在详细设计阶段确定。

## 5. 第一版明确不做

- 不提供 Qt 或其他图形界面。
- 不删除、移动、重命名或修改用户文件。
- 不连接数据库、网络或云存储。
- 不进行实时目录监控。
- 不实现复杂线程池。
- 不把内容指纹描述为安全审计或恶意文件检测。
- 不复制公司代码、图片、模型或业务数据。

## 6. 验收标准

MVP 同时满足以下条件才算完成：

- 使用当前约定的 C++20 工具链完成 Debug 和 Release 构建。
- 空目录能够正常结束并输出零文件结果。
- 嵌套目录中的普通文件能够被发现。
- 内容相同但文件名不同的文件能够被归入同一组。
- 内容不同但文件名相同的文件不会被错误归组。
- 文件读取失败时程序继续处理其他文件，并报告失败原因。
- 测试数据在运行时生成，不依赖个人盘符或外部业务数据。
- 自动化测试全部通过。
- 项目文档能够说明构建、运行、测试和关键设计取舍。

## 7. 后续方向

MVP 完成后的演进状态：

1. 进度显示已在 v0.1.0 完成，安全取消已在 v0.2.0 完成。
2. 有界并发内容指纹已在 v0.1.0 完成。
3. 报告导出仍是后续候选。
4. Qt 图形界面已在 v0.2.0 完成。

这些能力均按独立阶段讨论、设计和验收，没有提前混入 MVP 基线。
