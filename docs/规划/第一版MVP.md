# BatchGuard 第一版 MVP

> 状态：v0.1 已实现并通过验收。
>
> 分类：规划。
> 目标：先完成一个安全、可测试、真正能找出重复文件的命令行闭环。
> 本文是 v0.1 MVP 的历史产品基线；当前 v0.2.0 的 GUI、取消和结果展示范围见
> [第二版Qt界面.md](第二版Qt界面.md)。

## 1. 用户故事

作为需要整理本地目录的用户，我希望向程序提供一个目录，程序能够告诉我：

- 一共发现了多少个文件；
- 哪些文件内容完全相同；
- 哪些文件因为权限、占用或其他原因无法处理；
- 整个过程中不会修改我的任何文件。

## 2. 使用方式

MVP 基线接受一个目录位置参数：

```text
BatchGuard <目录路径>
```

示例：

```text
BatchGuard "E:\测试数据\待整理目录"
```

第一版同时提供：

```text
BatchGuard --help
BatchGuard --version
```

交付版本另外支持可选的哈希并发度：

```text
BatchGuard --hash-workers <1-64> <目录路径>
```

除以上内容外，第一版不增加其他命令行选项。

## 3. 输入规则

- 目录路径不能为空。
- 路径必须存在并且是目录。
- 支持包含空格和中文的 Windows 路径。
- 默认递归扫描所有子目录。
- 只处理普通文件。
- 不跟随目录符号链接，避免重复扫描或形成循环。
- 不对文件扩展名进行过滤。

输入无效时，程序输出明确原因并结束，不开始扫描。

## 4. 核心处理流程

```text
读取命令行
    ↓
验证目录
    ↓
递归发现普通文件
    ↓
读取文件大小
    ↓
按文件大小建立候选组
    ↓
只对同大小候选文件计算 SHA-256
    ↓
按“文件大小 + SHA-256”建立重复组
    ↓
生成并打印扫描报告
```

处理约束：

- 单个文件分块读取，不把完整文件一次性加载到内存。
- 一个文件失败时记录错误，并继续处理其他文件。
- 只有至少包含两个文件的组才算重复组。
- 文件名和路径不参与“内容是否相同”的判断。
- 输出顺序固定，便于人工阅读和自动化测试。

## 5. 内容指纹

v0.1 最终采用 SHA-256：

- 先按文件大小筛选候选文件，减少不必要的哈希计算。
- 只有“大小相同且 SHA-256 相同”时才归入同一重复组。
- SHA-256 只用于内容分组，不对外宣称安全审计能力。

实现最终选择 Windows CNG `BCrypt`，使用 64 KiB 固定缓冲区分块读取，不新增
密码学第三方依赖。

## 6. 控制台输出

正常报告至少包含：

```text
扫描目录：E:\测试数据
发现文件：8
成功处理：7
处理失败：1
重复组数：2

[重复组 1]
  E:\测试数据\a.txt
  E:\测试数据\备份\a_copy.txt

[重复组 2]
  E:\测试数据\photo.png
  E:\测试数据\old\photo_backup.png

[失败文件]
  E:\测试数据\locked.dat
  原因：无法读取文件
```

约定：

- 默认使用中文输出。
- 错误信息包含文件路径、失败阶段和可理解的原因。
- 无重复文件时明确输出“未发现重复文件”。
- 空目录属于正常结果，不属于错误。

## 7. 退出码

| 退出码 | 含义 |
|---:|---|
| `0` | 扫描完成，所有发现的文件均处理成功 |
| `1` | 命令行或输入目录无效，扫描未开始 |
| `2` | 扫描完成，但存在一个或多个文件处理失败 |
| `3` | 程序发生无法继续的内部错误 |

发现重复文件不是错误，不影响退出码。

## 8. 第一版数据结果

扫描结束后，程序在内存中应形成一份完整报告，概念上包含：

- 扫描根目录；
- 发现的文件总数；
- 成功处理数量；
- 失败文件及原因；
- 重复文件组；
- 扫描是否完整结束。

这里只定义结果包含什么，不提前决定具体类名和字段类型。

## 9. 异常与边界

第一版必须明确处理：

- 目录不存在；
- 输入路径是文件而不是目录；
- 空目录；
- 嵌套目录；
- 中文和空格路径；
- 零字节文件；
- 扫描过程中某个文件消失；
- 文件无权限或被占用；
- 两个文件大小相同但内容不同；
- 多于两个文件内容完全相同。

## 10. 明确不做

- 不提供图形界面。
- 不删除、移动、重命名或修改文件。
- 不自动选择“应该保留”的文件。
- 不导出 CSV 或 JSON。
- 不保存历史扫描记录。
- 不提供暂停、恢复或取消。
- 不进行多线程优化。
- 不扫描网络或云端目录。

以上是 MVP 基线的“不做项”。v0.1.0 最终交付增加了进度和有界并发，v0.2.0
增加了 Qt GUI 与安全取消；删除、移动、导出和历史记录至今仍不在范围内。

## 11. 验收用例

| 编号 | 场景 | 预期 |
|---|---|---|
| M-01 | 目录不存在 | 拒绝执行并返回 `1` |
| M-02 | 输入路径是普通文件 | 拒绝执行并返回 `1` |
| M-03 | 空目录 | 输出零文件、零重复组并返回 `0` |
| M-04 | 嵌套目录含多个文件 | 能够递归发现全部普通文件 |
| M-05 | 不同名称、内容相同 | 归入同一重复组 |
| M-06 | 名称相同、内容不同 | 不归入同一重复组 |
| M-07 | 大小相同、内容不同 | 不归入同一重复组 |
| M-08 | 两个零字节文件 | 归入同一重复组 |
| M-09 | 一个文件读取失败 | 继续处理其他文件并返回 `2` |
| M-10 | 中文和空格路径 | 正确扫描并完整显示路径 |
| M-11 | 三个文件内容相同 | 三个文件进入同一重复组 |

测试文件全部在测试运行时生成，不使用公司或个人业务数据。

## 12. 完成定义

以下条件全部满足，MVP 才算完成：

- Debug 和 Release 构建成功。
- M-01 至 M-11 均有可重复执行的测试或验证方式。
- 核心逻辑与控制台展示分离。
- 单个文件失败不会导致整个扫描中断。
- 程序不会修改被扫描目录中的任何内容。
- 文档包含构建、运行、测试方法和关键设计取舍。

## 13. 审查时需要确认

v0.1 采用以下默认选择：

1. 第一版只支持 Windows。
2. 控制台默认使用中文。
3. 默认递归扫描全部普通文件。
4. 使用“文件大小 + SHA-256”判断内容重复。
5. 存在单文件失败时返回退出码 `2`。

这些选择确认后才进入模块和接口设计。
