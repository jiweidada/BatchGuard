## 1. 使用说明

本文件用于在不同开发窗口之间传递当前状态。开始新会话时先阅读本文件和项目根
目录的 `AGENTS.md`，然后执行：

```powershell
git status --short --branch
```

实际 Git 状态优先于本文档。如果两者不一致，先查明原因并更新本文档，不要直接
开始下一阶段。

用户主要通过 CLion 手动选择文件、Commit 和 Push。未经用户明确要求，不要自动
提交或推送。

## 2. 长期开发规则

- 使用 C++20、CMake、Ninja 和 GoogleTest。
- 公共核心头文件放入 `include/batchguard/core/`。
- 核心实现放入 `src/core/`。
- CLI 代码放入 `apps/cli/`。
- 单元测试放入 `tests/unit/`。
- 每个阶段编写独立的 `docs/测试/阶段N测试.md`。
- 第三方源码统一放入 `Third_Party/<library>/`，不直接修改。
- 核心库不得依赖 CLI 或未来 GUI。
- `main.cpp` 只处理程序边界、对象组装和异常兜底。
- 项目自有代码注释必须使用中文。
- 注释内容和位置遵循 Google C++ Style Guide 的 Comments 章节。
- 第三方源码注释保持上游原貌，不翻译或修改。
- 文件系统预期错误使用 `std::error_code`。
- 文件系统测试使用运行时生成的临时目录和数据，不依赖固定盘符或个人路径。
- 不提交 `build/`、`cmake-build-*/` 和 `.idea/`。

## 8. 阶段 4 边界

阶段 4 计划范围：

- 读取文件大小。
- 按文件大小建立候选组。
- 使用 SHA-256 计算内容指纹。
- 分块读取文件，不一次性加载完整文件。
- 单个文件读取失败时记录失败并继续。
- 添加阶段 4 GTest。
- 编写 `docs/测试/阶段4测试.md`。

阶段 4 应作为新的独立提交，不修改已经完成的阶段 3 提交。

阶段 4 已采用以下技术方案：

- Windows CNG `BCrypt` SHA-256，不新增第三方依赖。
- 64 KiB 固定缓冲区分块读取。
- 先读取文件大小，只哈希至少有两个成员的同大小候选组。
- 元数据失败记录为 `Metadata`，文件打开或读取失败记录为 `Hashing`。
- 单文件失败不终止其他文件处理。
- 本阶段不建立重复组或完整 `ScanReport`。
