# BatchGuard 第一版实现

> 状态：v0.1 已实现并完成最终交付验收。
>
> 分类：设计。
> 本文说明第一版 MVP 如何落地；产品行为和验收用例以
> [第一版MVP.md](../规划/第一版MVP.md) 为准。

## 1. 实现目标

第一版交付一个 Windows 命令行程序：

```text
BatchGuard <目录路径>
BatchGuard --hash-workers <1-64> <目录路径>
BatchGuard --help
BatchGuard --version
```

程序递归发现普通文件，先按大小筛选候选，再计算 SHA-256，根据“大小 +
SHA-256”建立重复组，最后输出中文报告和明确退出码。扫描过程只读，不删除、
移动、重命名或修改用户文件。

MVP 基线不要求 GUI、报告导出、历史记录、实时监控、取消或并发。功能正确并完成
全量回归后，阶段 8 增加了有界文件级并发；其余能力仍不在 v0.1 范围内。

## 3. 总体架构

```text

    │
    ▼

    │
    ▼

    │
    ▼

    │
    ▼

    │
    ▼

    │
    ▼

    │
```

目标依赖保持单向：

```text

batchguard_tests ────> batchguard_core
```

- CLI 不重新实现扫描、哈希或分组规则。
- 测试直接调用核心库，不依赖完整 CLI。

## 5. 核心数据类型

以下名称作为第一版设计起点，可在单个增量审查时调整：

### `FailureStage`

使用 `enum class` 表示失败阶段：

```text
Discovery
Metadata
Hashing
```

### `FileFailure`

记录：

- 发生失败的路径。
- 失败阶段。
- `std::error_code`。
- 面向用户的可理解原因。

### `FileRecord`

记录：

- 文件路径。
- 文件大小。
- 需要时计算出的 SHA-256。

### `DuplicateGroup`

记录：

- 文件大小。
- SHA-256。
- 至少两个成员路径。

### `ScanReport`

记录：

- 扫描根目录。
- 发现的普通文件数量。
- 成功处理数量。
- 失败记录。
- 重复文件组。
- 扫描是否完整结束。

所有对象优先使用值语义和标准容器，不为第一版引入动态多态或共享所有权。

## 6. CLI 与输入验证

CLI 只接受一个位置参数，以及 `--help`、`--version`。

参数结果应区分：

```text
Scan
ShowHelp
ShowVersion
Invalid
```

输入验证使用 `std::filesystem` 的 `std::error_code` 重载，依次检查：

1. 参数存在且非空。
2. 路径可以查询。
3. 路径存在。
4. 路径是目录。

第一版优先支持 Windows 中文和空格路径。Windows CLI 边界使用宽字符参数，
核心层接收 `std::filesystem::path`，避免先把中文路径错误转换成窄字符串。

输入无效时不启动扫描，输出原因并返回 `1`。

## 7. 文件发现

文件发现模块递归遍历输入目录：

- 只收集普通文件。
- 不跟随目录符号链接。
- 不按扩展名过滤。
- 使用 `std::error_code` 处理目录和文件状态查询。
- 单个目录项失败时记录 `FileFailure`，继续遍历。
- 结果按路径稳定排序，确保报告和测试可重复。

文件发现不负责计算哈希或打印错误。

发现数量只统计成功识别出的普通文件。目录遍历错误单独进入失败记录，不伪装成
已经发现的文件。

## 8. 大小候选分组

发现文件后读取文件大小，并按 `std::uintmax_t` 分组：

```text
size -> [file1, file2, ...]
```

- 只有一个成员的大小组不可能重复，无需计算 SHA-256。
- 至少两个成员的大小组进入哈希阶段。
- 文件大小读取失败时记录 `Metadata` 失败。
- 唯一大小且元数据读取成功的文件仍计为成功处理。

该步骤是性能筛选，不改变最终以文件内容判断重复的规则。

## 9. SHA-256 实现

第一版建议使用 Windows CNG `BCrypt`：

- Windows 系统自带，不增加运行时 DLL 部署。
- 使用 SHA-256 系统实现，避免自行编写密码学算法。
- Windows 细节封装在 `file_hasher.cpp`，不暴露到公共头文件。
- `batchguard_core` 通过 CMake 链接 `bcrypt`。

文件读取采用固定大小缓冲区，建议第一版使用 64 KiB：

```text
打开文件
  → 初始化 SHA-256
  → 循环读取 64 KiB
  → 更新哈希状态
  → 生成最终摘要
```

约束：

- 不一次性读取完整文件。
- 零字节文件也生成标准 SHA-256。
- 文件打开或读取失败进入 `Hashing` 失败。
- 一个文件失败不影响其他文件。
- 摘要统一表示为小写十六进制字符串。

引入 `BCrypt` 前，单独确认其接口封装、错误映射和 CMake 链接方式。

## 10. 重复分组

对成功完成哈希的候选文件，按以下键分组：

```text
(文件大小, SHA-256)
```

只有至少两个成员的组进入最终报告。文件名和路径不参与内容相等判断。

为保证结果稳定：

- 每组成员路径排序。
- 重复组按文件大小、摘要和首个路径排序。
- 展示层只读取分组结果，不重新判断重复关系。

第一版按 MVP 约定使用“大小 + SHA-256”，不额外进行逐字节二次比较。

## 11. 扫描编排

`scanner` 模块按固定顺序调用：

```text
validateInput
    ↓
discoverFiles
    ↓
readMetadataAndGroupBySize
    ↓
hashCandidateFiles
    ↓
findDuplicateGroups
    ↓
buildScanReport
```

预期文件错误作为数据进入报告；只有程序无法维持基本状态时才允许异常到达应用
边界。`main` 统一捕获不可恢复异常并返回 `3`。

成功处理数量定义为：完成自身所需处理且未产生文件级失败的已发现普通文件。唯一
大小文件不需要哈希，但仍属于成功处理。

## 12. 中文报告

控制台报告至少包含：

```text
扫描目录：E:\测试数据
发现文件：8
成功处理：7
处理失败：1
重复组数：2

[重复组 1]
  E:\测试数据\a.txt
  E:\测试数据\备份\a_copy.txt

[失败文件]
  路径：E:\测试数据\locked.dat
  阶段：读取内容
  原因：无法读取文件
```

特殊结果：

- 无重复文件：明确输出“未发现重复文件”。
- 空目录：输出零文件、零重复组，返回 `0`。
- 有局部失败：输出所有可用结果，返回 `2`。

CLI 展示层负责把错误阶段和错误码转换成中文说明。

## 13. 退出码

| 退出码 | 触发条件 |
|---:|---|
| `0` | 扫描完成，所有发现文件处理成功 |
| `1` | 命令行或输入目录无效，扫描未开始 |
| `2` | 扫描完成，但存在局部文件失败 |
| `3` | 不可恢复的内部错误 |

发现重复文件不是错误，不改变退出码。

## 14. 测试方案

第一版采用 GoogleTest 1.17.0 编写断言，通过 CTest 统一运行。源码固定安装在
`Third_Party/googletest/`，CMake 使用 `add_subdirectory` 接入，不在每个构建
目录重复下载。GoogleTest 只作为构建依赖，不进入产品业务逻辑。

测试公共要求：

- 使用临时目录。
- 测试运行时生成文件内容。
- 使用 RAII 清理测试目录。
- 不依赖固定盘符、执行顺序或外部业务数据。
- 每个测试只验证一个主要行为。

### 单元测试

- CLI 参数解析。
- 输入目录验证。
- 文件发现。
- 大小候选分组。
- SHA-256 已知输入。
- 重复分组。
- 报告统计与退出码映射。

### 集成测试

| 编号 | 场景 | 主要阶段 |
|---|---|---|
| M-01 | 目录不存在 | 输入验证 |
| M-02 | 输入为普通文件 | 输入验证 |
| M-03 | 空目录 | 完整流程 |
| M-04 | 嵌套目录 | 文件发现 |
| M-05 | 不同名称、内容相同 | 重复分组 |
| M-06 | 名称相同、内容不同 | 重复分组 |
| M-07 | 大小相同、内容不同 | SHA-256 |
| M-08 | 两个零字节文件 | SHA-256 |
| M-09 | 一个文件读取失败 | 失败隔离 |
| M-10 | 中文和空格路径 | Windows 路径 |
| M-11 | 三个文件内容相同 | 多成员分组 |

M-09 在 Windows 测试中使用测试辅助代码独占打开文件，稳定制造读取失败；不依赖
个人机器上的权限配置。

## 15. CMake 目标

计划目标：

```text
batchguard_core   静态核心库
batchguard_cli    命令行程序，输出名 BatchGuard
batchguard_tests  自动化测试
```

建议增加构建选项：

```cmake
option(BATCHGUARD_BUILD_TESTS "Build BatchGuard tests" ON)
```

测试开启时：

```cmake
enable_testing()
add_subdirectory(tests)
```

业务代码不得依赖 GoogleTest。`bcrypt` 只链接到需要 SHA-256 实现的最小目标。
