# BatchGuard 项目结构

> 状态：v0.1 和 v0.2.0 已实现，阶段 18 Release 交付验收完成。
>
> 分类：设计。

## 1. 设计目标

- 核心业务不依赖命令行、Qt 或其他界面框架。
- 每个 CMake 目标职责单一，依赖方向清晰。
- 公共接口与私有实现分离。
- 单元测试和集成测试能够独立运行。
- 后续增加 GUI 时不重写核心逻辑。

## 3. 目录职责

### `include/batchguard/core`

- 存放 `batchguard_core` 对外公开的头文件。
- 只暴露调用方真正需要的类型和函数。
- 不引用 CLI 或未来 GUI 的头文件。

### `src/core`

- 存放核心模块实现与不公开的辅助头文件。
- 负责文件扫描、结果建模、哈希编排和重复分组等业务能力。
- 不负责参数解析、终端输出或窗口控件。

### `include/batchguard/logging` 和 `src/logging`

- 存放标准 C++20 结构化日志记录、格式化和线程安全终端输出。
- 统一使用“时间：信息类型：所属层：信息内容”的单行 UTF-8 格式。
- 不依赖 Qt，不记录输入目录或文件完整路径，也不负责持久化日志文件。
- `batchguard_core` 不反向依赖日志设施；应用层根据核心进度建立日志记录。

### `apps/cli`

- 存放命令行入口和 CLI 专属代码。
- 负责读取参数、调用核心库并把结果展示给用户。
- `main.cpp` 只做对象组装和流程启动，不承载核心算法。

### `apps/gui`

- 存放 Qt GUI 入口、窗口、控制器和 GUI 专属适配代码。
- 阶段 12 已将最小窗口替换为正式扫描设置和状态界面。
- `main.cpp` 只创建 `QApplication`、组装并显示主窗口。
- Qt 类型不得进入 `include/batchguard/core/` 或 `src/core/`。
- `ScanController` 是控件状态和扫描终态的唯一来源。
- `ThreadedScanExecution` 管理专用扫描线程、进度节流和停止请求。
- 结果摘要和三个只读模型只持有不可变报告及轻量索引。
- `GuiLogModel` 只显示非 `DEBUG` 的简化状态，最多保留最近 500 条。
- `terminal_console` 只连接父控制台，不为资源管理器启动额外创建控制台窗口。

### `tests/unit`

- 测试单个类或函数。
- 使用临时文件和运行时生成的数据。
- 不启动完整应用。

### `tests/integration`

- 测试“目录输入 → 扫描 → 哈希 → 重复分组 → 输出”的完整流程。
- 不依赖个人路径和外部业务数据。

### `Third_Party`

- 集中保存固定版本的第三方源码及其许可证。
- CMake 从本地目录接入，避免不同构建目录重复下载。
- 不直接修改上游源码；新增或升级依赖必须单独审查并使用独立提交。
- 第三方库只链接到实际使用它的最小目标。

## 4. CMake 目标

当前固定使用五个基础项目目标，并在 GUI 选项开启时增加三个 GUI 目标：

| 目标 | 类型 | 职责 |
|---|---|---|
| `batchguard_core` | 静态库 | 纯 C++20 核心能力 |
| `batchguard_logging` | 静态库 | 结构化日志记录、格式化和终端输出 |
| `batchguard_cli_support` | 静态库 | 可测试的 CLI 应用层和控制台展示 |
| `batchguard_cli` | 可执行程序 | 命令行交互 |
| `batchguard_tests` | 测试程序 | 核心单元与集成测试 |
| `batchguard_gui_support` | 可选静态库 | 主窗口、控制器和 Qt 适配 |
| `batchguard_gui` | 可选 GUI 程序 | 创建 Qt 应用并组装主窗口 |
| `batchguard_gui_tests` | 可选测试程序 | GUI 状态和控件行为 |

`BATCHGUARD_BUILD_GUI` 默认关闭。关闭时不执行 `find_package(Qt5)`；开启时
`batchguard_gui` 使用 `AUTOMOC`、`AUTOUIC` 和 Qt5 Widgets，输出
`BatchGuardGui.exe`。本机 Qt SDK 路径通过 `CMAKE_PREFIX_PATH` 或 CLion Profile
提供，不硬编码到项目中。

Windows GUI 链接完成后，CMake 使用同一 Qt 套件中的 `windeployqt`，把本地运行
需要的 Qt DLL 和平台插件部署到可执行文件目录。部署命令显式优先使用该 Qt 套件的
`bin`，避免 Anaconda 或其他 Qt 安装污染依赖解析。构建产物继续由 Git 忽略。

## 5. 依赖方向

```text
batchguard_cli ──────> batchguard_cli_support ──────> batchguard_core
                              │
                              └─────────────────────> batchguard_logging

batchguard_tests ────> batchguard_cli_support
batchguard_tests ────> batchguard_core
batchguard_tests ────> batchguard_logging

batchguard_gui ───────> batchguard_gui_support ──────> batchguard_core
                                      │
                                      ├──────────────> batchguard_logging
                                      └──────────────> Qt5::Widgets
batchguard_gui_tests ─> batchguard_gui_support ──────> Qt5::Test
```

- `batchguard_core` 不得反向依赖任何应用目标。
- `batchguard_core` 不依赖 `batchguard_logging`，日志输出策略属于应用边界。
- CLI 与 GUI 不互相依赖。
- GUI 支持层只通过公共核心接口访问业务；后台线程调用核心可取消扫描。
- 第三方库必须由使用它的最小目标链接，避免污染整个项目。

## 6. 文件放置规则

- 一个主要类或一组紧密相关的小类型对应一对 `.h/.cpp`。
- 公共头文件路径与命名空间保持一致。
- 私有辅助类型不放入 `include/`。
- 测试文件使用 `<被测模块>_test.cpp` 命名。
- 平台相关实现必须隔离，不能在业务代码中散落大量条件编译。

## 7. 第一个框架增量（已完成）

第一笔代码改动完成了以下内容：

1. 将语言标准从 C++26 调整为 C++20。
2. 建立 `batchguard_core` 和 `batchguard_cli` 两个空目标。
3. 将现有入口移动到 `apps/cli/main.cpp`。
4. 保证程序仍只输出一条启动信息并成功构建。

该增量不包含扫描、哈希、线程或 Qt 代码。

## 8. 阶段 10 Qt 增量（已完成）

阶段 10 增加：

1. 默认关闭的 `BATCHGUARD_BUILD_GUI` 选项。
2. 条件化的 Qt5 Widgets 包查找。
3. `batchguard_gui` Windows GUI 目标。
4. 使用 Qt Designer `.ui`、`AUTOMOC` 和 `AUTOUIC` 的最小主窗口。
5. 与 CLI 输出名不冲突的 `BatchGuardGui.exe`。
6. 使用匹配 Qt 套件自动部署本地运行库和 Windows 平台插件。

本增量不包含目录输入、扫描、线程、取消、进度或结果展示业务。

## 9. 阶段 11 核心安全取消增量（已完成）

阶段 11 增加：

1. 公共 `ScanStatus` 和 `ScanResult`，取消时不提供 `ScanReport`。
2. 带 `std::stop_token` 的可取消扫描重载。
3. 发现、元数据、任务领取、单文件读取块和重复分组停止检查。
4. 可取消哈希调度结果，以及工作线程返回前的 RAII 回收。
5. 不依赖 Qt 的取消集成测试和调度器可控测试。

原有 `scanDirectory` 重载、CLI 依赖方向和报告语义保持兼容。本增量不接入
`QThread`、GUI 控件或真实后台扫描。

## 10. 阶段 12 GUI 状态机增量（已完成）

阶段 12 增加：

1. `batchguard_gui_support` 和 `batchguard_gui_tests`。
2. 正式主窗口的目录、线程数、开始、取消和状态控件。
3. `Idle`、`Scanning`、`Cancelling`、`Completed`、`Cancelled` 和 `Failed`
   六态控制器。
4. 可替换 `ScanExecution` 边界、重复启动保护和旧扫描事件隔离。
5. 使用可控假执行器的 Qt Test 自动化测试。

本增量没有建立真实工作线程，也没有调用大目录扫描。阶段 13 将在现有执行边界后
接入核心安全取消接口。

## 11. 阶段 13 后台扫描增量（已完成）

阶段 13 增加：

1. 使用专用 `QThread` 调用核心可取消扫描的 `ThreadedScanExecution`。
2. 四阶段进度文本、固定刻度映射和约 100 ms 普通事件节流。
3. 完成、取消和失败结果在线程回收后向 GUI 控制器发送。
4. 扫描中关闭窗口时先请求停止、终态到达后自动关闭的流程。
5. 真实临时目录后台扫描、取消、线程回收和关闭窗口测试。

核心库不依赖 Qt；GUI 不直接访问私有核心实现，也不从扫描线程操作控件。

## 12. 阶段 14 结果展示增量（已完成）

阶段 14 增加：

1. 核心报告的总逻辑字节、候选文件与字节和完成指纹数。
2. 使用饱和累计的 `ResultSummary` 和易读字节格式。
3. `DuplicateGroupModel`、`DuplicatePathModel` 和 `FailureModel`。
4. 六项指标、扫描详情、重复组主从表和失败页签。
5. 复制完整路径、打开所在目录、空结果和取消结果处理。

模型共享不可变 `ScanReport`，不为每个单元格复制业务对象；易读文本和原始排序值
使用不同数据角色。

## 13. 阶段 15 GUI 自动化增量（已完成）

阶段 15 增加初始窗口、中文空格目录、四阶段进度、零字节候选、64 位字节映射、
结果模型角色和选择联动覆盖，并修复未知总量发现阶段未显示累计文件数的问题。
GUI 行为测试增加到 23 项。

## 14. 阶段 16 结构化日志增量（已完成）

阶段 16 增加：

1. 独立的 `batchguard_logging` 标准 C++20 静态库。
2. 带毫秒和时区、类型、稳定层级、摘要及附加字段的单行日志格式。
3. 线程安全 `TerminalLogSink`，CLI 完整日志固定写入标准错误流。
4. GUI 父控制台连接和完整日志输出；资源管理器启动时不新建控制台。
5. 只读 `GuiLogModel`，过滤 `DEBUG`、隐藏附加字段并限制最近 500 条。
6. CLI 参数、扫描阶段和 GUI 开始、取消、完成、失败生命周期日志。

日志不写文件，不包含输入目录或文件完整路径。GUI 状态、核心业务和报告结构保持
原有依赖方向及只读边界。

## 15. 阶段 17 界面验收增量（已完成）

阶段 17 没有改变核心业务和依赖方向。真实 GUI 验收发现完成态日志区域会挤压结果
表，因此主内容改为可滚动区域，日志面板保持紧凑高度。最小窗口下可通过滚动访问
完整结果，默认窗口直接显示结论和重复组表，并由 Qt Test 固化布局可达性。

## 16. 阶段 18 Release 交付（已完成）

项目版本更新为 `0.2.0`。Release 仍使用现有目标和依赖方向，不新增运行时业务层。
Qt DLL、平台插件、部署目录和本机 SDK 路径只作为本地交付验证产物，由
`.gitignore` 排除；正式部署步骤和许可证材料记录在 `docs/交付/`。
