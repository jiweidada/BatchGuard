# BatchGuard 项目结构

> 状态：v0.1 已实现，v0.2.0 阶段 11 已建立纯 C++ 核心安全取消。
>
> 分类：设计。

## 1. 设计目标

- 核心业务不依赖命令行、Qt 或其他界面框架。
- 每个 CMake 目标职责单一，依赖方向清晰。
- 公共接口与私有实现分离。
- 单元测试和集成测试能够独立运行。
- 后续增加 GUI 时不重写核心逻辑。

## 3. 目录职责

### `include/batchguard/core`

- 存放 `batchguard_core` 对外公开的头文件。
- 只暴露调用方真正需要的类型和函数。
- 不引用 CLI 或未来 GUI 的头文件。

### `src/core`

- 存放核心模块实现与不公开的辅助头文件。
- 负责文件扫描、结果建模、哈希编排和重复分组等业务能力。
- 不负责参数解析、终端输出或窗口控件。

### `apps/cli`

- 存放命令行入口和 CLI 专属代码。
- 负责读取参数、调用核心库并把结果展示给用户。
- `main.cpp` 只做对象组装和流程启动，不承载核心算法。

### `apps/gui`

- 存放 Qt GUI 入口、窗口和后续 GUI 专属适配代码。
- 阶段 10 只包含最小窗口，用于验证 Qt Debug 构建、链接和窗口生命周期。
- `main.cpp` 只创建 `QApplication`、组装并显示主窗口。
- Qt 类型不得进入 `include/batchguard/core/` 或 `src/core/`。
- 扫描控制器、后台工作对象和结果模型只在后续阶段按需创建。

### `tests/unit`

- 测试单个类或函数。
- 使用临时文件和运行时生成的数据。
- 不启动完整应用。

### `tests/integration`

- 测试“目录输入 → 扫描 → 哈希 → 重复分组 → 输出”的完整流程。
- 不依赖个人路径和外部业务数据。

### `Third_Party`

- 集中保存固定版本的第三方源码及其许可证。
- CMake 从本地目录接入，避免不同构建目录重复下载。
- 不直接修改上游源码；新增或升级依赖必须单独审查并使用独立提交。
- 第三方库只链接到实际使用它的最小目标。

## 4. CMake 目标

当前固定使用四个 v0.1 项目目标，并在 GUI 选项开启时增加一个阶段 10 目标：

| 目标 | 类型 | 职责 |
|---|---|---|
| `batchguard_core` | 静态库 | 纯 C++20 核心能力 |
| `batchguard_cli_support` | 静态库 | 可测试的 CLI 应用层和控制台展示 |
| `batchguard_cli` | 可执行程序 | 命令行交互 |
| `batchguard_tests` | 测试程序 | 核心单元与集成测试 |
| `batchguard_gui` | 可选 GUI 程序 | 阶段 10 Qt 最小窗口 |

`BATCHGUARD_BUILD_GUI` 默认关闭。关闭时不执行 `find_package(Qt5)`；开启时
`batchguard_gui` 使用 `AUTOMOC`、`AUTOUIC` 和 Qt5 Widgets，输出
`BatchGuardGui.exe`。本机 Qt SDK 路径通过 `CMAKE_PREFIX_PATH` 或 CLion Profile
提供，不硬编码到项目中。

Windows GUI 链接完成后，CMake 使用同一 Qt 套件中的 `windeployqt`，把本地运行
需要的 Qt DLL 和平台插件部署到可执行文件目录。部署命令显式优先使用该 Qt 套件的
`bin`，避免 Anaconda 或其他 Qt 安装污染依赖解析。构建产物继续由 Git 忽略。

后续阶段计划增加 `batchguard_gui_support` 和 `batchguard_gui_tests`，但在对应
实现出现前不提前创建空目标。

## 5. 依赖方向

```text
batchguard_cli ──────> batchguard_cli_support ──────> batchguard_core
batchguard_tests ────> batchguard_cli_support
batchguard_tests ────> batchguard_core
batchguard_gui ───────> Qt5::Widgets
```

- `batchguard_core` 不得反向依赖任何应用目标。
- CLI 与 GUI 不互相依赖。
- 阶段 10 的 GUI 不链接核心业务；真实扫描将在 GUI 支持层建立后接入。
- 第三方库必须由使用它的最小目标链接，避免污染整个项目。

## 6. 文件放置规则

- 一个主要类或一组紧密相关的小类型对应一对 `.h/.cpp`。
- 公共头文件路径与命名空间保持一致。
- 私有辅助类型不放入 `include/`。
- 测试文件使用 `<被测模块>_test.cpp` 命名。
- 平台相关实现必须隔离，不能在业务代码中散落大量条件编译。

## 7. 第一个框架增量（已完成）

第一笔代码改动完成了以下内容：

1. 将语言标准从 C++26 调整为 C++20。
2. 建立 `batchguard_core` 和 `batchguard_cli` 两个空目标。
3. 将现有入口移动到 `apps/cli/main.cpp`。
4. 保证程序仍只输出一条启动信息并成功构建。

该增量不包含扫描、哈希、线程或 Qt 代码。

## 8. 阶段 10 Qt 增量（已完成）

阶段 10 增加：

1. 默认关闭的 `BATCHGUARD_BUILD_GUI` 选项。
2. 条件化的 Qt5 Widgets 包查找。
3. `batchguard_gui` Windows GUI 目标。
4. 使用 Qt Designer `.ui`、`AUTOMOC` 和 `AUTOUIC` 的最小主窗口。
5. 与 CLI 输出名不冲突的 `BatchGuardGui.exe`。
6. 使用匹配 Qt 套件自动部署本地运行库和 Windows 平台插件。

本增量不包含目录输入、扫描、线程、取消、进度或结果展示业务。

## 9. 阶段 11 核心安全取消增量（已完成）

阶段 11 增加：

1. 公共 `ScanStatus` 和 `ScanResult`，取消时不提供 `ScanReport`。
2. 带 `std::stop_token` 的可取消扫描重载。
3. 发现、元数据、任务领取、单文件读取块和重复分组停止检查。
4. 可取消哈希调度结果，以及工作线程返回前的 RAII 回收。
5. 不依赖 Qt 的取消集成测试和调度器可控测试。

原有 `scanDirectory` 重载、CLI 依赖方向和报告语义保持兼容。本增量不接入
`QThread`、GUI 控件或真实后台扫描。
