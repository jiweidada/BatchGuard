# BatchGuard 阶段 13 测试

> 状态：真实后台扫描、进度与取消 Debug 验证完成（2026-07-30）。
>
> 测试范围：专用扫描线程、真实核心报告、四阶段进度、安全取消和窗口关闭。

## 1. 实现边界

`ThreadedScanExecution` 使用一个专用 `QThread` 调用核心同步扫描接口。核心哈希线程
仍由 `batchguard_core` 管理，GUI 线程不执行目录遍历、文件读取或哈希。执行器只在
扫描线程结束并回收后，才向控制器发送完成、取消或失败终态。

进度适配遵循以下规则：

- 发现、元数据、哈希和分组阶段都转换为 GUI 状态文字和进度条。
- 普通事件最多约每 100 ms 发送一次。
- 阶段变化和阶段完成事件始终发送。
- 未知总数使用忙碌进度，零字节候选按文件数显示。
- 64 位字节数先计算比例再映射到固定刻度，避免整数溢出。
- 控制器继续按扫描编号忽略旧事件。

## 2. 自动化场景

阶段 13 在 `batchguard_gui_tests` 中增加：

1. 真实临时目录在后台完成扫描并返回不可变报告。
2. GUI 事件定时器能在扫描期间运行，证明主线程事件循环保持响应。
3. 四个核心进度阶段按顺序到达，阶段变化不被节流丢弃。
4. 工作线程中的停止请求返回 `Cancelled`，不产生部分报告。
5. 终态发送前专用扫描线程已经回收。
6. 扫描中关闭窗口先取消，线程结束后窗口自动关闭。
7. 取消请求与完成事件竞争时，控制器保持 `Cancelled`，不展示完成报告。
8. 扫描执行器在工作线程结束事件尚未处理时销毁，线程对象仍被确定性回收。

测试数据全部在运行时临时目录中生成，不依赖个人路径或业务文件。

GUI 已通过真实后台线程调用核心扫描，主线程只处理状态和控件。取消与关闭都等待
