# BatchGuard 阶段 14 测试

> 状态：扫描统计与结果展示 Debug 验证完成（2026-07-30）。
>
> 测试范围：核心基础统计、结果摘要、重复组与路径模型、失败模型、空结果和大量结果。

## 1. 实现范围

核心 `ScanReport` 新增以下稳定基础统计：

- 成功读取元数据文件的总逻辑字节数。
- 内容指纹候选文件数和候选逻辑字节数。
- 成功完成内容指纹的候选文件数。

GUI 从完整且不可变的报告推导重复文件数、冗余副本数、重复内容总逻辑大小和理论
可节省空间。所有字节累计使用饱和运算；“理论可节省”明确标注为逻辑大小估算，
不代表已经释放或一定能够释放物理空间。

正式结果区包含：

- 一句自然语言结论和六项主要指标。
- 总逻辑大小、候选文件与字节、完成指纹数和扫描耗时详情。
- 每组一行的重复组主表，默认按理论可节省空间降序。
- 所选组的完整路径表，以及复制路径和打开所在目录操作。
- 按发现、元数据和哈希阶段展示的失败表与阶段汇总。
- 无重复项、无失败项和取消结果的明确空状态。

## 2. 自动化场景

新增或扩展测试覆盖：

1. 核心报告的总逻辑字节、候选数量、候选字节和完成指纹数量。
2. 重复文件数、冗余副本和理论可节省空间的统计口径。
3. 超大字节乘法与累计饱和，不发生整数回绕。
4. 易读大小与原始 64 位排序值分离。
5. 重复组默认按理论可节省空间降序，并保持稳定组号。
6. 选择重复组后，路径模型只读取对应组的完整路径。
7. 失败阶段、路径、原因和阶段汇总。
8. 5000 个重复组的大量结果模型。
9. 完整报告显示结论和表格；取消结果不显示为完整报告。
10. 空重复结果和空失败结果显示明确提示。

既有跨目录重复、同大小不同内容、零字节重复和锁定文件测试继续作为核心行为回归。

## 3. Debug 验证

```powershell
cmake --build cmake-build-debug --target clean
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
ctest --test-dir cmake-build-debug -R BatchGuardGuiTests --repeat until-fail:20
```

实际结果：

- 公共报告结构变化后执行 Debug 干净重建，全部目标构建成功。
- CTest 共发现 84 项，0 失败，1 项 Skipped。
- 当前 Windows 实际执行 83 项并全部通过。
- `BatchGuardGuiTests` 连续运行 20 轮全部通过。
- 目录符号链接测试继续因本机权限标记为 Skipped。
- 没有创建或验证 Release；Release 回归延后到阶段 17。

## 4. 阶段结论

GUI 已能从真实完整报告展示统计、重复组、路径和失败详情，空结果和取消结果不会
造成误导。界面仍保持只读，不提供删除、移动或重命名。阶段 15 可以在现有 Qt Test
入口上继续补齐更细的 GUI 自动化覆盖。
