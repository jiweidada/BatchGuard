# BatchGuard 阶段 10 测试

>

## 1. 测试目标

验证阶段 10 满足以下边界：

- `BATCHGUARD_BUILD_GUI` 默认关闭。
- 关闭 GUI 时不执行 Qt 包查找，CLI 和核心测试保持原行为。
- 开启 GUI 时使用 Qt 5.14.2 `msvc2017_64` 和 MSVC x64。
- `AUTOMOC`、`AUTOUIC`、中文界面文本和 `WIN32` GUI 入口能够构建。
- Debug 生成独立的 `BatchGuardGui.exe`。
- Debug 最小窗口能够启动、接收正常关闭消息并以退出码 `0` 退出。
- GUI 目标不链接 `batchguard_core`，本阶段不接入扫描业务。
- 原 CLI 和 73 项 CTest 没有回归。
- Release 配置、运行库部署和干净环境验收不属于当前验证范围。

CMake 配置中明确指定 MSVC 和 Ninja。该处理只影响本次终端进程，没有修改系统
环境变量或项目 CMake 中的本机绝对路径。

## 3. Qt 构建

当前开发统一使用 CLion CMake Profile，不再建立单独的 `build/`。Debug Profile
使用 `cmake-build-debug`，并配置：

```text
-DBATCHGUARD_BUILD_GUI=ON
-DBATCHGUARD_BUILD_TESTS=ON
-DCMAKE_PREFIX_PATH=<本机 Qt 5.14.2 msvc2017_64 目录>
```

CLion 完成配置后，可在已加载 MSVC 环境的终端复用同一目录：

```powershell
cmake --build cmake-build-debug --target batchguard_gui
ctest --test-dir cmake-build-debug --output-on-failure
```

必须运行 CMake 目标 `batchguard_gui`，不能直接运行编辑器生成的单文件
`main.cpp` 配置。单文件命令 `cl.exe apps/gui/main.cpp /Femain` 不包含项目的
`/utf-8`、Qt include、链接库和代码生成步骤，会产生 `C4819` 与 `C1083`，不能
用于判断项目源码是否可构建。

构建确认生成：

```text
cmake-build-debug/BatchGuardGui.exe
cmake-build-debug/batchguard_gui_autogen/include/ui_main_window.h
cmake-build-debug/batchguard_gui_autogen/*/moc_main_window.cpp
cmake-build-debug/Qt5Widgetsd.dll
cmake-build-debug/Qt5Cored.dll
cmake-build-debug/platforms/qwindowsd.dll
```

GUI 链接后，CMake 从 `Qt5::qmake` 定位匹配的 `windeployqt`。部署子进程将该 Qt
套件的 `bin` 置于 `PATH` 首位，避免 Anaconda 中另一套 Qt 干扰依赖解析。Qt DLL、
插件和其他构建产物均位于被 Git 忽略的 `cmake-build-*` 目录。

## 5. 实际结果

- Qt Debug 配置、编译和链接成功。
- Qt Debug 生成 `BatchGuardGui.exe`。
- Debug 最小窗口成功显示标题 `BatchGuard GUI`。
- 窗口接受正常关闭消息，并在 5 秒内以退出码 `0` 结束。
- `AUTOMOC` 生成 `moc_main_window.cpp`。
- `AUTOUIC` 生成 `ui_main_window.h`，中文标签成功进入窗口。
- CLion `cmake-build-debug` 已包含 GUI 的完整编译数据库和 Qt include 参数。
- CMake 构建后自动调用匹配版本的 `windeployqt`。
- 直接启动 `cmake-build-debug/BatchGuardGui.exe` 成功，不依赖临时修改全局 `PATH`。
- CLion Debug 默认 `all` 目标重建后，CTest 发现 73 项，0 失败，1 项 Skipped，
  总耗时约 0.50 秒。
- 首次完整 Qt Debug CTest 总耗时约 0.61 秒。
- 本轮复核 Debug CTest 总耗时约 0.50 秒。
- Debug CTest 发现 73 项，实际执行 72 项并全部通过。
- 目录符号链接测试继续因本机权限标记为 Skipped，与 v0.1.0 一致。
- 原独立 `build/` 已按当前开发约定删除，后续统一使用 CLion 的
  `cmake-build-debug`。
- 当前不创建或维护 `cmake-build-release`；Release 验证延后到阶段 17。
- `cmake-build-*` 继续由 `.gitignore` 排除，没有构建产物进入 Git。

## 6. 阶段结论

Qt 5.14.2 `msvc2017_64`、MSVC 19.29、Ninja 1.13.2 和 CMake 4.2.0-rc1 在当前
BatchGuard C++20 项目中能够完成 Debug 配置、代码生成、链接和最小窗口运行。
阶段 10 的 Debug 验证通过，可以进入阶段 11 的纯 C++ 核心安全取消设计与实现；
Release 配置、部署和验收延后到阶段 17。
