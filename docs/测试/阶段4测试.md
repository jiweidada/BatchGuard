# BatchGuard 阶段 4 测试

> 状态：实现验收通过（2026-07-29）。
>
> 测试范围：文件大小候选筛选、SHA-256 分块计算和失败隔离，不包含重复分组或
> 完整扫描报告。

## 1. 测试目标

验证阶段 4 满足以下条件：

- 为成功读取元数据的普通文件保存 `std::uintmax_t` 文件大小。
- 只有同大小组至少包含两个文件时才计算 SHA-256。
- 已知内容和零字节文件生成标准 SHA-256。
- 使用 64 KiB 固定缓冲区分块读取，不一次性加载完整文件。
- 摘要使用 64 个字符的小写十六进制字符串。
- 中文和带空格路径能够正常计算内容指纹。
- 元数据或哈希失败形成对应阶段的 `FileFailure`。
- 单个文件失败时继续处理其他文件。
- 文件记录和失败记录按照稳定顺序返回。
- CLI 显示元数据、内容指纹和处理失败数量。

## 3. 功能实现位置与调用链

### 3.1 总体调用流程

```text
runCli
    ↓
discoverFiles
    ↓
fingerprintFileCandidates
    ├── std::filesystem::file_size
    ├── 按文件大小建立候选组
    └── calculateFileSha256
            ├── CreateFileW
            ├── BCrypt SHA-256
            └── ReadFile 64 KiB 循环
    ↓
ContentFingerprintResult
    ├── fileRecords
    └── failures
    ↓
CLI 输出阶段四计数和退出码
```

### 3.2 文件职责

| 文件 | 主要职责 |
|---|---|
| `file_hasher.h/.cpp` | 封装 Windows CNG、文件句柄和分块 SHA-256 |
| `content_fingerprint.h/.cpp` | 读取大小、筛选候选、编排哈希和稳定排序 |
| `file_failure.h` | 增加 `Metadata` 和 `Hashing` 失败阶段 |
| `cli_app.cpp` | 串联发现与指纹流程，显示数量并映射退出码 |
| `content_fingerprint_test.cpp` | 直接测试阶段四核心行为 |
| `cli_app_test.cpp` | 验证 CLI 阶段四统计和局部失败退出码 |

### 3.3 技术选择

- 使用 Windows CNG `BCrypt`，避免自行实现密码学算法或新增第三方依赖。
- 使用 RAII 封装文件、算法提供者和哈希句柄。
- 打开文件时允许其他读取者，但不共享写入，避免哈希期间内容被并发修改。
- 使用 64 KiB 固定缓冲区循环调用 `ReadFile` 和 `BCryptHashData`。
- CNG 操作失败使用独立 `std::error_category` 保存原始 `NTSTATUS`。
- Windows 文件打开和读取失败使用 `std::system_category()` 保存 `GetLastError()`。
- 唯一大小文件仍属于元数据处理成功，但其 `sha256` 保持为空。

## 8. 阶段结论

阶段 4 实现验收通过：

- Windows CNG `BCrypt` 能够生成标准小写 SHA-256。
- 64 KiB 固定缓冲区能够正确处理空文件和跨多个读取块的大文件。
- 文件大小筛选避免对唯一大小文件进行不必要的哈希。
- `Metadata` 和 `Hashing` 失败使用 `FileFailure` 返回，单文件失败不终止批处理。
- 核心结果按路径稳定排序，CLI 显示阶段四处理数量和局部失败退出码。
- Debug、Release 构建成功，CTest 为 36/36、0 失败。
- 本阶段没有建立重复文件组，也没有引入阶段五的完整 `ScanReport`。

代码与文档仍需由开发者在 CLion 中审查、提交并推送。
