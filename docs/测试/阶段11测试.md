# BatchGuard 阶段 11 测试

> 状态：核心协作式安全取消 Debug 验证完成（2026-07-30）。
>
> 测试范围：取消结果语义、扫描各阶段停止传播、多线程任务领取、工作线程回收、
> 旧扫描接口兼容以及 Debug 全量回归。

## 1. 测试目标

验证阶段 11 满足以下边界：

- 核心取消只使用 C++20 `std::stop_token`，不依赖 Qt。
- 已经请求停止的扫描不开始工作，也不产生进度事件。
- 停止请求传播到文件发现、元数据读取、哈希任务领取、单文件读取块和重复分组。
- 取消返回独立的 `ScanStatus::Cancelled`，不生成可展示的 `ScanReport`。
- 局部文件失败仍返回 `ScanStatus::Completed` 和带失败记录的报告。
- 多线程哈希收到停止请求后不再执行新任务，并在返回前回收全部工作线程。
- 未请求停止时，新接口结果与原有 `scanDirectory` 接口一致。
- CLI 继续使用原接口，参数、输出和退出码行为不变。

## 2. 接口语义

原有三个 `scanDirectory` 重载保持不变并继续返回 `ScanReport`。阶段 11 新增带
`std::stop_token` 的四参数重载，返回 `ScanResult`：

| 终态 | `ScanResult::status` | `report` |
|---|---|---|
| 完整结束，包括局部文件失败 | `Completed` | 有值 |
| 响应外部停止请求 | `Cancelled` | 无值 |
| 致命异常 | 不返回 | 保持原行为，异常向上传播 |

因此，局部文件失败仍可通过 `ScanReport::isComplete()` 判断；取消不会经过
`ScanReport`，不能再被空 `failures` 误判为完整成功。

## 4. Debug 验证命令

普通 PowerShell 没有完整 MSVC include 环境时，先加载 Visual Studio 2019 x64
开发环境，再复用 CLion Debug 构建目录：

```powershell
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
```

公共结果结构发生变化后，本机增量构建曾保留旧测试对象，MSVC 运行时因此检测到
对象布局不一致。执行一次 Debug 干净重建后全部对象使用相同头文件布局，问题消失。
这属于本机构建缓存问题，不是取消调度死锁；诊断期间没有保留临时代码或构建产物。

## 5. 实际结果

- Debug 全量干净重建成功。
- 阶段 11 的 9 项新增测试全部通过。
- CTest 发现 82 项，0 失败，1 项 Skipped。
- 当前 Windows 实际执行 81 项并全部通过。
- 目录符号链接测试继续因本机权限标记为 Skipped，与既有结果一致。
- Debug CTest 总耗时约 0.60 秒。
- 多线程停止领取测试重复运行 100 轮，全部通过。
- 原有并发哈希、进度、扫描报告、CLI 和文件系统测试均无回归。
- 没有创建或验证 Release 构建；Release 回归延后到阶段 18。

## 6. 阶段结论

阶段 11 已建立不依赖 Qt 的核心协作式安全取消。停止请求能够到达扫描的全部主要
处理边界，多线程哈希使用 RAII 回收工作线程，取消终态不会产生可展示的部分报告。
原 CLI 接口和未取消扫描语义保持兼容，可以进入阶段 12 的 GUI 主窗口与状态机设计。
