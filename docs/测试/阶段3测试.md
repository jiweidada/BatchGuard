# BatchGuard 阶段 3 测试

> 状态：实现验收通过（2026-07-29）。
>
> 测试范围：递归普通文件发现、稳定排序、失败记录和路径处理，不包含文件大小、
> 哈希或重复分组。

## 1. 测试目标

验证阶段 3 满足以下条件：

- 有效目录能够进入递归文件发现流程。
- 空目录正常返回零文件、零失败。
- 能够发现任意嵌套层级中的普通文件。
- 不按扩展名过滤文件。
- 不跟随目录符号链接。
- 单个目录或目录项失败时形成 `FileFailure`，不抛出预期文件系统异常。
- 文件路径和失败记录按照稳定顺序返回。
- 中文和带空格路径能够正常发现并完整显示。
- 文件发现只查询目录项状态，不读取或修改文件内容。

## 3. 功能实现位置与调用链

### 3.1 总体调用流程

```text
wmain
    ↓
runCli
    ↓
validateInputDirectory
    ↓
discoverFiles
    ↓
FileDiscoveryResult
    ├── filePaths
    └── failures
    ↓
CLI 输出发现数量和退出码
```

### 3.2 文件职责

| 文件 | 主要职责 |
|---|---|
| `file_failure.h` | 定义失败阶段和单路径失败信息 |
| `file_discovery.h` | 定义文件发现结果和公共接口 |
| `file_discovery.cpp` | 递归枚举、类型判断、失败隔离和稳定排序 |
| `cli_app.cpp` | 在输入验证后调用发现模块，显示数量并映射退出码 |
| `file_discovery_test.cpp` | 直接测试核心文件发现行为 |
| `cli_app_test.cpp` | 验证 CLI 能够展示发现数量 |

### 3.3 核心实现步骤

```text
将根目录放入待处理目录栈
    ↓
使用带 std::error_code 的 directory_iterator 打开目录
    ↓
使用 symlink_status 查询目录项类型
    ├── 符号链接：跳过
    ├── 目录：加入待处理目录栈
    ├── 普通文件：加入发现结果
    └── 其他类型：忽略
    ↓
记录打开、状态查询或枚举失败
    ↓
按原生路径排序文件和失败记录
```

使用显式目录栈而不是把业务处理堆入 CLI，可以在一个目录失败后继续处理其他
已经发现的待处理目录，并保持核心模块独立。

## 8. 阶段结论

阶段 3 实现验收通过：

- 能够递归发现空目录、嵌套目录及中文空格路径中的普通文件。
- 不按扩展名过滤，不把目录或符号链接计入普通文件。
- 预期文件系统失败使用 `std::error_code` 转换为 `FileFailure`。
- 文件路径和失败记录按照稳定顺序返回。
- CLI 能够显示发现文件数、发现失败数和阶段范围。
- 发现完整时返回 `0`，存在局部发现失败时返回 `2`。

- 当前实现不读取文件大小、不计算哈希，也不判断重复文件。
