# BatchGuard 阶段 9 测试

> 状态：最终交付验收完成（2026-07-29）。
>
> 测试范围：版本与帮助、README 成功路径、退出码、输出重定向、只读性、交付
> 文档以及 Debug、Release 最终全量回归。

## 1. 测试目标

验证 v0.1.0 满足以下交付条件：

- 新用户可以按 README 配置、构建、测试和运行。
- `--help`、`--version` 和扫描命令与文档一致。
- 完整扫描、输入错误、局部失败和内部错误分别映射到退出码 `0`、`1`、`2`、`3`。
- 输出连接文件或管道时不产生动态进度文本。
- 单线程和多线程生成相同的最终报告。
- 重复扫描不会修改输入文件。
- 构建产物和 IDE 设置没有进入 Git。
- 版本变更记录、架构说明、演示步骤和面试问答齐全。
- Debug、Release 构建和自动化测试通过。

## 3. 程序边界验证

| 编号 | 场景 | 结果 |
|---|---|---|
| S9-01 | `BatchGuard --help` | 返回 `0`，用法与 README 一致 |
| S9-02 | `BatchGuard --version` | 返回 `0`，输出 `BatchGuard 0.1.0` |
| S9-03 | 不提供参数 | 返回 `1` |
| S9-04 | 提供未知选项 | 返回 `1` |
| S9-05 | 一个候选文件被独占锁定 | 其他文件继续，最终返回 `2` |
| S9-06 | 1 线程和 4 线程扫描同一目录 | 返回 `0`，最终报告完全一致 |
| S9-07 | 标准输出由工具捕获 | 不包含动态进度文本 |
| S9-08 | 重复扫描同一测试目录 | 文件内容和最后写入时间不变 |

不可恢复异常由 `wmain` 统一转换为退出码 `3`。自动化测试不主动制造进程级资源
耗尽或未知异常，以免形成不稳定或破坏性的验收步骤。

## 4. 最终构建与测试

Debug：

```powershell
cmake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug
ctest --test-dir build/debug --output-on-failure
```

Release：

```powershell
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/release
ctest --test-dir build/release --output-on-failure
```

## 5. 实际结果

- Debug 配置和构建成功，没有新增编译警告。
- Release 配置和构建成功，没有新增编译警告。
- Debug 和 Release CTest 均发现 73 个测试，0 个失败。
- 当前 Windows 实际执行 72 个测试并通过。
- 目录符号链接测试因当前机器没有创建符号链接权限而标记为 Skipped。
- Debug CTest 总耗时约 0.59 秒。
- Release CTest 总耗时约 0.41 秒。
- `--help` 和 `--version` 返回 `0`。
- 缺少参数和未知选项返回 `1`。
- 自动化锁定文件场景返回 `2`，其他候选继续处理。
- 1 线程和 4 线程最终报告完全一致。
- 非控制台输出不包含动态进度文本。
- 重复扫描只读性测试通过。
- `.gitignore` 覆盖 `build/`、`cmake-build-*/` 和 `.idea/`。
- Git 未跟踪任何构建产物或 IDE 私有配置。

## 6. 阶段结论

BatchGuard 0.1.0 满足 MVP 完成定义和总大纲的最终交付物要求。真实存储介质上的
并发性能比较属于后续调优，不阻塞 v0.1.0 的正确性和交付验收。
