# 阶段 18 测试记录

> 日期：2026-07-31
>
> 配置：MSVC 19.29、Ninja、Qt 5.14.2 `msvc2017_64`

> 结论：v0.2.0 Release 构建、测试、部署和干净环境启动验收通过。

## 1. Release 配置与构建

新建规划指定的 `cmake-build-release`，配置：

```text
CMAKE_BUILD_TYPE=Release
BATCHGUARD_BUILD_GUI=ON
BATCHGUARD_BUILD_TESTS=ON
```

Release CLI、GUI、核心库、支持库、GoogleTest 和 Qt Test 均成功编译链接。
`BatchGuard.exe --version` 输出 `BatchGuard 0.2.0` 并返回 `0`。

## 2. Debug 与 Release 回归

```powershell
ctest --test-dir cmake-build-debug --output-on-failure
ctest --test-dir cmake-build-release --output-on-failure
ctest --test-dir cmake-build-release --output-on-failure `
    --repeat until-fail:20 -R BatchGuardGuiTests
```

实际结果：

- Debug CTest：88 项，0 失败，1 项 Skipped。
- Release CTest：88 项，0 失败，1 项 Skipped。
- 两种配置均实际执行 87 项并通过。
- Release GUI 测试连续运行 20 轮通过。
- 跳过项为当前账户无符号链接创建权限。

## 3. Release CLI 真实扫描

在 `cmake-build-release` 中运行时生成中文空格子目录、两个重复文件和一个唯一文件。
Release CLI 使用四个哈希线程扫描：

- 发现文件：3。
- 成功处理：3。
- 处理失败：0。
- 重复组：1。
- 退出码：`0`。

测试数据随后删除，没有进入版本控制。

## 4. Qt 部署

独立部署目录包含：

- `BatchGuard.exe` 和 `BatchGuardGui.exe`。
- `Qt5Core.dll`、`Qt5Gui.dll`、`Qt5Widgets.dll` 和 `Qt5Svg.dll`。
- `platforms/qwindows.dll`、图像格式、图标引擎和系统样式插件。
- `LICENSE.Qt.txt`。

共 22 个文件、47,463,394 字节，没有 Debug Qt DLL。

首次直接调用 `windeployqt` 时，当前终端的 Anaconda PATH 导致工具错误解析其他
发行版的 `Qt5Widgets.dll`。使用目标 Qt `bin` 和 Windows 系统目录构成的临时
PATH 后部署成功。部署文档已明确记录该环境隔离要求。

## 5. 干净环境启动

进程级环境中清除 `QT_PLUGIN_PATH`、`QML2_IMPORT_PATH`，PATH 仅保留 Windows
系统目录，然后从独立部署目录启动：

- CLI 输出 `BatchGuard 0.2.0`，退出码 `0`。
- GUI 成功创建主窗口。
- GUI 接收正常关闭请求后优雅退出，退出码 `0`。

`dumpbin /dependents` 确认 GUI 直接 Qt 依赖为 Core、Gui 和 Widgets。目标机器还需
安装 Microsoft Visual C++ 2019 x64 Redistributable。
