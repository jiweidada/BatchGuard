# 阶段 17 测试记录

>

> 结论：Debug GUI 的真实扫描、取消、关闭、日志、DPI 和布局验收通过。

## 1. 验收范围

- 空目录。
- 中文和空格目录。
- 多个重复文件组和零字节重复文件。
- 1,500 个以上普通文件。
- 独占锁定文件形成部分失败。
- 大体积候选扫描中取消。
- 扫描中关闭窗口。
- 同一窗口连续执行多次扫描。
- 父终端完整日志和 GUI 简化日志。
- Windows 100%、125% 和 150% 缩放。
- 默认窗口、最小窗口和最大化布局。

测试数据均在 `cmake-build-debug` 中临时生成，验收后删除；没有使用真实业务目录，
也没有把路径、截图或扫描报告写入仓库。

## 2. 真实扫描结果

中文空格测试目录包含 1,507 个文件，覆盖三个普通重复文件、两个零字节重复文件、
另一对重复候选和 1,500 个运行时生成的小文件。真实 Debug GUI 结果为：

- 扫描文件：1,507。
- 成功处理：1,507。
- 重复组：3。
- 涉及重复文件：7。
- 冗余副本：4。
- 理论可节省：102.0 KiB。
- 处理失败：0。

结果表显示三个重复组，选择首组后显示三条完整路径。完成后在同一窗口再次扫描，
仍进入 `Completed`，没有遗留旧扫描线程或错误状态。

空目录能够瞬时完成，不出现空白或失败终态。该场景完成速度快于 50 ms 轮询间隔，
验收脚本因此按最终状态判断，不把“未观察到按钮禁用瞬间”误判为失败。

## 3. 失败、取消和关闭

独占打开一个候选文件后运行真实 GUI：

- 最终状态为“扫描完成，存在部分失败”。
- GUI 日志出现 `WARN：扫描控制：扫描完成，存在部分失败`。
- 结果页显示“处理失败（1）”。
- 其他文件和重复组继续处理。

对两个各 256 MiB 的运行时候选文件开始扫描后点击取消：

- 状态进入“扫描已取消，可以重新开始”。
- 取消结果不展示为完整报告。
- GUI 日志不包含测试目录路径。

在相同大候选扫描期间关闭窗口：

- 窗口先发出协作式停止请求。
- 进程约 54 ms 后自行退出。
- 退出码为 `0`，没有强制终止或遗留 `BatchGuardGui` 进程。

## 4. 日志验收

GUI 面板只显示简化的时间、类型、中文层和摘要，扫描目录不出现在日志文本中。

从独立 Windows CMD 启动 `BatchGuardGui.exe` 后，父终端实际显示：

```text
时间：INFO：GUI.ScanExecution：GUI 应用启动
时间：INFO：GUI.ScanController：界面已就绪
时间：INFO：GUI.ScanExecution：GUI 应用结束，exitCode=0
```

GUI 退出后 CMD 保持可用。从资源管理器等无父终端入口启动时，程序不创建额外
控制台窗口。

## 5. DPI 和布局验收

分别设置 `QT_SCALE_FACTOR=1.0`、`1.25` 和 `1.5`：

- 三种缩放下真实 Debug GUI 均能启动和关闭。
- 三种缩放下 `BatchGuardGuiTests` 均通过。
- 标题、目录输入、线程数、状态、日志和结果文字未发现重叠或截断。

首次完成态视觉检查发现：日志面板会挤压结果区域，默认窗口中重复组表只露出表头。
本阶段已修复：

- 主内容改为可滚动区域。
- 日志面板高度上限设为 190。
- 日志列表保持 80 至 120 的紧凑高度。
- 默认窗口顶部可直接看到结果摘要和重复组表。
- 向下滚动可完整访问三组结果、路径表和路径操作按钮。
- 最小窗口下结果仍可滚动访问。

新增 `mainWindowKeepsCompletedResultsReachableAtMinimumSize` 回归测试，GUI 行为测试
由 25 项增加到 26 项。

## 6. 最终回归

修复后执行：

```powershell
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
ctest --test-dir cmake-build-debug --output-on-failure `
    --repeat until-fail:20 -R BatchGuardGuiTests
```

- GUI 测试连续运行 20 轮全部通过。
- GUI 测试在 100%、125% 和 150% 缩放下分别通过。
