# BatchGuard 阶段 7 测试

> 状态：实现和自动化验收完成（2026-07-29）。
>
> 测试范围：核心扫描进度事件、分块字节进度、CLI 事件转发、动态控制台进度条和
> 标准输出重定向兼容。

## 1. 测试目标

验证阶段 7 满足以下条件：

- 核心库不依赖控制台，通过同步回调报告进度。
- 进度阶段固定为发现、元数据、哈希和重复分组。
- 文件发现阶段在总数未知时报告累计发现数量。
- 元数据阶段报告已处理文件数和发现文件总数。
- 哈希阶段报告候选文件数及分块读取字节数。
- 哈希失败后仍完成阶段进度，并继续生成部分报告。
- CLI 在真实 Windows 控制台中动态刷新一行进度。
- 动态刷新最多约每 100 毫秒一次，阶段切换和阶段完成强制显示。
- 标准输出连接文件或管道时不写入回车刷新字符。
- 进度显示不额外输出当前文件名或完整路径。
- 原有一参数公共接口保持兼容。

## 3. 进度事件设计

### `ScanProgressStage`

```text
Discovery → Metadata → Hashing → Grouping
```

枚举顺序就是扫描执行顺序，便于调用方验证和展示。

### `ScanProgress`

| 字段 | 含义 |
|---|---|
| `stage` | 当前处理阶段 |
| `completedItems` | 已完成文件或工作项数量 |
| `totalItems` | 工作项总数；发现阶段未知时为 `0` |
| `completedBytes` | 哈希阶段累计处理字节数 |
| `totalBytes` | 所有哈希候选的总字节数 |
| `isStageComplete` | 当前事件是否为阶段最终状态 |

进度回调在扫描线程内同步执行，不引入并发、共享可变状态或额外线程。

## 4. 核心调用链

```text
scanDirectory(progressCallback)
    ↓
discoverFiles
    └── 累计发现数量
    ↓
fingerprintFileCandidates
    ├── 元数据文件数量
    └── calculateFileSha256
            └── 每个 64 KiB 读取块的累计字节数
    ↓
findDuplicateGroups
    └── 报告生成开始与完成
```

原有不需要进度的调用方继续使用一参数重载；新调用方使用带回调的二参数重载。

## 5. CLI 显示规则

- `main.cpp` 使用 `GetConsoleMode` 判断标准输出是否连接真实控制台。
- 真实控制台通过 `ConsoleProgressRenderer` 使用回车在当前行刷新。
- 阶段切换时保留上一阶段最终状态并换行。
- 进度条宽度固定为 20 个字符。
- 哈希阶段优先按字节计算百分比；零字节候选按文件数计算。
- 最终扫描报告在进度显示结束后正常输出。
- 文件或管道重定向不创建进度回调，因此没有刷新字符或额外进度文本。

## 9. 实际结果

- Debug 构建成功，没有新增编译错误。
- Release 构建成功，没有新增编译错误。
- 阶段 7 的 6 项重点测试全部通过。
- Debug 和 Release CTest 均发现 59 个测试，0 个失败。
- 当前 Windows 实际执行 58 个测试并通过。
- 目录符号链接测试因当前机器没有创建符号链接权限而标记为 Skipped。
- Debug CTest 总耗时约 0.40 秒。
- Release CTest 总耗时约 0.27 秒。
- 1,000,000 字节文件的分块进度单调递增，最终值等于文件大小。
- 候选文件读取失败后，哈希阶段仍到达完成状态并继续生成部分报告。
- 控制台渲染器验证了四阶段文本、进度条、百分比和禁用时零输出。
- 使用真实的 7 文件目录运行 Debug CLI，返回 `0` 并正确输出 1 个跨目录重复组。
- 工具捕获下标准输出不是控制台，实际 CLI 只输出最终报告，没有动态进度文本。
